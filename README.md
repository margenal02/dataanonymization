# 隐数盾：数据安全平台

面向内网部署的可逆数据脱敏应用。原始文件在本地完成敏感信息替换，脱敏稿可交由外部 AI 校对、总结或改写；AI 处理后的文件再上传本系统，使用原任务的加密映射恢复正式信息。

## 功能

- 支持 `.xls`、`.docx`、`.pdf`、`.ofd`、`.txt`。
- 默认支持最大 200 MB 的单文件上传；Web 页面会在上传前按服务端配置校验大小，超限时返回明确提示。
- 本地 UIE-base 与规则词典协同识别单位/部门、人员姓名、品牌/产品、产区/地点、电话、身份证、邮箱和地址；扫描 PDF 默认使用移动版检测/识别模型的“极速文字 OCR”，复杂版面可切换 PP-StructureV3 版面增强模式，业务文件不会发送到云端。
- Web 页面可选择“临时调用”或“模型常驻”；也可维护烟草专卖局、卷烟厂、供应商和人员标签。
- “模型中心”可安全导入、激活、导出和删除本机 UIE 微调权重。模型包逐文件生成 SHA-256 清单，导出不包含原始文档、本地标签、匿名映射或部署密钥。
- 上传后先进入人工确认：完整提取文本按页/片段预览，所有相同字段的出现位置按类型着色；候选项同时显示识别来源、置信度和类型，操作人员确认勾选后才开放脱敏文件下载。
- 人工确认采用左右双栏工作台：左侧滚动预览全文，右侧管理候选；可直接在原文中划选漏识别字段，选择类别后点击箭头加入人工补充清单。
- 系统可独立识别“陆良厂、云南复烤、贵州复烤、河北中烟”等行业常用简称，也能理解“陆良、泸西、石林厂”“陆良、泸西、石林三厂”“陆良、泸西、石林等3家复烤厂”等顿号并列、中心词后置的口语省略表达。顿号、数量词和“厂/复烤厂”保持原样，只替换名称部分。系统还会从已识别单位全称生成同文档简称候选，例如“陆良复烤厂 / 陆良”“云南烟叶复烤有限责任公司 / 云南复烤”。只有人工确认后才共用匿名代码，并要求指定反匿名时统一恢复的标准名称。
- 每个任务使用独立可逆映射；匿名标记带有由本机映射密钥派生的安装标识，例如 `【A1B2C3D4-单001】`、`【A1B2C3D4-人001】`。复制脱敏稿本身不能恢复原文，必须同时拥有原任务的本机加密映射和密钥。
- 匿名映射使用 Fernet 对称加密后保存到 MySQL，不提供明文映射下载。
- 脱敏文件下载、原任务关联、反匿名恢复和任务历史均在同一工作台完成。
- 上传文件标题自动生成任务名称；文件名中的已识别敏感信息同步脱敏，反匿名时恢复正式文件名；每条记录保存原始上传、脱敏输出、反匿名上传稿和正式输出。
- 删除记录时同步删除该任务的全部保存文件和加密映射。
- “质量洞察”聚合展示任务完成率、候选采纳/否决、人工补漏、类别修正、同实体合并、敏感类别/文件格式分布和识别耗时；分析接口不返回敏感原文。
- Docker Compose 一键本地部署，对外端口固定为 `5291`。

本地识别器覆盖单位、部门、角色上下文人名、人员名单、产品、地区、电话、证件、邮箱和规范地址，并由 UIE-base 补充上下文识别。人名结果采用更高分类阈值并执行姓氏/结构校验；模型同一词出现类别冲突时会按置信度和类别优先级裁决。一个字段只要在文档任一位置被规则、标签或模型确认，系统就以 Unicode 规范化视图定位全文中的同一字段，兼容全半角、不可见控制字符、OCR 插入空格和 Word 跨文字节点等差异；实际写文件时只替换命中区间，不重写周围句子。正文和文件名共用可逆映射。系统不会把自动识别直接当作最终结论：候选项必须在全文高亮复核区人工勾选，也可取消误报、修改类别或补录漏项；每个确认字段都会作为加密本机标签保存。重新校正时当前编号保持稳定，已移除或合并的历史编号作为只读恢复别名保留，因此旧脱敏稿仍可关联原任务反匿名。

扫描 PDF 无需再手工预处理：后端逐页检查文本层，只对没有足够文本的页面执行 OCR。Web 默认选择“极速文字 OCR”，只加载 `PP-OCRv5_mobile_det` 和 `PP-OCRv5_mobile_rec`；复杂多栏或版面文档可手动选择“版面增强 OCR”，额外加载 `PP-DocLayout-S`。两种模式均关闭表格重建、公式、印章、图表和文档矫正。OCR 子进程退出并释放内存后才加载 UIE-base；校正后重新脱敏会直接复用首次加密保存的逐页识别文本，不再重复 OCR。系统同一时间只运行一个重型脱敏任务，Web 显示当前页、OCR 页数和进度，并提供“中断脱敏”按钮安全终止 OCR 子进程。默认渲染 150 DPI、最长边 2480 像素，最多 OCR 300 页、总文字 500000 字符、单页最长 180 秒；可在 `.env` 中调整。

“临时调用”只在本次脱敏期间加载 UIE-base，任务结束后释放模型内存，适合偶尔使用或 16 GB 内存的电脑，但每次任务会有模型启动等待；“模型常驻”首次加载后保留模型进程，连续处理速度更快，空闲时通常占用约 2～4 GB 内存，建议至少 32 GB 系统内存。“训练标注工作台”支持上传文档、规则与 UIE 机器预标、全文彩色复核、取消/改类/划词补标；保存结果后新词条立即进入本地精确识别库，同时加密保存带原文上下文和字符位置的训练样本，并可流式导出与线上提示词完全一致、包含人工复核负样本的 UIE JSONL 训练集。保存标注不会把少量样本冒充成已完成的 UIE 权重训练，集中微调应在样本量和验证集达到要求后单独执行。

## 技术结构

```text
浏览器 :5291
    │
  Nginx ── /api/* ── Django REST API ── MySQL 8
    │                         │
    └── Vue 3 + Bootstrap 5   ├── 加密映射与本地文件处理
                              ├── 极速文字 / PP-StructureV3 版面增强 OCR 子进程
                              └── 本地 UIE-base 进程（临时/常驻）
```

## Windows + WSL2 + Docker 部署

Windows 10/11 中国大陆网络环境只需一个 `install-wsl-docker-cn.ps1`。脚本先检测系统，检测合格后询问是否继续；选择“是”后检查现有 WSL2、Ubuntu、Docker 和 Compose，版本符合要求时自动跳过重复安装。在管理员 PowerShell 中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install-wsl-docker-cn.ps1
```

如只做检测，可为同一脚本添加 `-CheckOnly`。完整流程、支持版本、国内镜像配置、重启续跑和故障排查参见 [Windows + WSL2 + Docker 中国大陆一键安装说明](docs/WSL_DOCKER_CN_INSTALL.md)。

PP-StructureV3 精简模式与 UIE-base 组合的最低部署配置为 8 个逻辑核心、16 GB 内存和 50 GB 可用空间，建议配置为 12 个及以上逻辑核心、32 GB 内存和 80 GB 可用 SSD 空间。16～31 GB 内存的主机必须优先选择“临时调用”。首次构建会安装 PaddleOCR/PaddleNLP，并把精简 OCR 模型和 UIE-base 封装进后端镜像，耗时和镜像体积会明显增加。

安装过程持续记录到 `.runtime/install-support-latest.log`。如果脚本报错、窗口异常关闭或需要协助排查，直接发送这一份日志即可；不要发送包含密码和加密密钥的 `.env` 文件。正常及已捕获的失败运行会另存带时间的历史日志，未正常结束的日志会在下次运行前自动抢救归档。

WSL 系统包只使用微软官方来源；`Auto`/`Web` 会先对 GitHub 官方直连及大陆反向代理做小文件实测，验证文件头后选择最快通道，再通过 Windows 原生 `curl.exe` 下载微软签名的 WSL MSI 和微软清单中的 Ubuntu 包。窗口每 0.5 秒在同一个动态进度区域内更新真实百分比、已下载/总大小、瞬时及平均 MB/s，不会连续新增下载记录，并支持断点续传和缓存复用。首次系统资源检测拆分为 10 个可见小步骤，逐项记录 WMI、DISM、端口和镜像源选择。Ubuntu、Docker CE 与 PyPI 会用 `curl.exe` 对清华、阿里云、USTC、华为云、腾讯云、北外 BFSU 和南京大学 NJU 做小流量实测并选择最快可用源；npm 会在 npmmirror、华为云和腾讯云中选择最快候选，全部不可用时再回退官方源。单个候选失败或超时不会终止整个安装。WSL 内 Docker 准备阶段细分为“检查 Ubuntu 源、配置 Python 镜像、安装 Docker、配置容器镜像、启用 systemd”5 个可见步骤；进度条只显示 UTF-8 结构化中文状态和安全的 ASCII 原始诊断，避免 ConHost 把子进程中文重复转码成乱码。容器部署另拆分为 11 个可见小步骤，持续显示已等待时间、最近的安全诊断及健康检查次数；Docker 构建使用 BuildKit 纯文本明细，并把后端、前端完整输出分别保存到 `.runtime/docker-build-backend.log` 与 `.runtime/docker-build-frontend.log`。如果旧 MySQL 数据卷密码与当前 `.env` 不一致，脚本会在检测到 `ERROR 1045` 后通过禁用网络的临时维护容器无损同步账号密码，不删除数据库、任务记录或文件。脚本优先创建 `DataAnonymizationWslKeepAlive` 登录自动启动任务，使 WSL、Docker 和容器在安装窗口关闭后继续运行；系统策略拒绝计划任务时自动降级为当前登录会话隐藏后台保活，并明确提示重启后的恢复方法。脚本从 Windows 连续检查网站稳定性与实际保活状态后才报告完成。代理传输内容仍必须通过官方 SHA-256 和微软数字签名校验。现有 WSL、发行版和 Docker 检测有 12～20 秒超时保护；旧版 `wsl.exe` 的 UTF-16/系统代码页输出也会自动解码。

安装完成后优先访问 [http://127.0.0.1:5291](http://127.0.0.1:5291)，`http://localhost:5291` 为备用地址。日常运维统一进入 WSL2：

```powershell
wsl -d Ubuntu-24.04 -u root
```

进入 WSL 后切换到项目目录，再执行 Docker Compose 命令：

```bash
cd /mnt/d/code/dataanonymization  # 按实际项目路径修改
docker compose ps                 # 查看状态
docker compose logs -f            # 查看日志
docker compose down               # 停止服务，保留数据
docker compose up -d              # 重新启动
```

## Linux 主机 + Docker 部署

Linux 服务器无需 WSL，推荐 Ubuntu Server 22.04/24.04 LTS。Docker Engine 支持范围为 `>=24.0 且 <30.0`，Compose 插件为 `>=2.20 且 <6.0`；现有版本符合范围时无需重新安装。安装 Docker、配置中国大陆镜像、安全密钥、防火墙、启动与备份步骤参见 [Linux 主机 Docker 部署说明](docs/LINUX_DOCKER_DEPLOYMENT.md)。

## 使用流程

1. 在“数据匿名”选择 UIE-base 的“临时调用”或“模型常驻”，上传原文件并勾选识别类型；16～31 GB 内存请选择“临时调用”。
2. 在自动打开的人工确认区查看全文彩色预览：保留需要脱敏的勾选项，取消误报，必要时修改类型；漏项可直接在左侧原文划选，在右侧选择类别并点击箭头加入，也可按 `类别|内容` 手工输入。对系统列出的全称/简称组逐一判断是否合并，并指定反匿名标准名称。
3. 点击“确认选择并生成脱敏文件”；未完成这一步时，前端和后端都不允许下载候选脱敏稿。
4. 下载脱敏文件交由 AI 处理，不要删除、拆分或改写正文中的 `【单001】`、`【人001】` 等标记或文件名中的 `ANON_单001` 等标记。
5. 如需修改识别选择，可在结果或历史记录中重新校正；新版文件会保持仍有效字段的原匿名编号，并保留旧编号的恢复兼容。随后返回“数据反匿名”，选择原任务、上传新旧任一脱敏稿并下载正式文件。

长期复用的字段可在“训练标注工作台”单条添加，也可上传样本文档完成机器预标和人工校正；只用于当前任务的内容可填写在“指定敏感词”中。人工确认的每个候选字段（包括电话、证件、邮箱和自定义项）及补录内容都会加密保存为本机标签并在后续任务中生效，人工取消项保存为加密负样本；如果管理员关闭强制人工确认，最终进入脱敏文件的自动候选视为已接受并同样保存。文档标注保存时会记录上下文位置并进入可导出的 UIE JSONL 训练集。停用标签只停止精确词库匹配，已有训练样本仍保留，便于审计和未来批量微调。

指定敏感词每行一个；可用 `类型|内容` 标注：

```text
单位|某某市烟草专卖局
单位|某某卷烟厂
人名|张三
产品|文山雨露
产区|文山
某内部项目代号
```

## 文件处理说明

PDF/OFD 的详细实现与限制参见 [PDF 与 OFD 处理机制说明](docs/FILE_PROCESSING_GUIDE.md)。

微调权重包的目录格式、安全限制、导入导出和在其他部署中复用的方法参见 [UIE 模型包导入导出说明](docs/MODEL_PACKAGE_GUIDE.md)。

本轮面向数据质量、后端性能、安全边界和前端信息架构的系统审查参见 [产品、数据与技术架构审查报告](docs/ARCHITECTURE_REVIEW.md)。

| 格式 | 处理方式 | 注意事项 |
|---|---|---|
| TXT | 保留检测到的文本编码，必要时转 UTF-8 BOM | 结构保真度最高 |
| DOCX | 处理正文、表格、页眉页脚、文本框及 WPS/PDF 转 Word 常见的 DrawingML 文字；仅改写命中的文字区间 | 保留原 XML 文字节点与样式；图片文字仍需 OCR |
| XLS | 保留工作簿和主要单元格样式 | 只处理文本单元格，不改写公式 |
| PDF | 文本页直接提取，扫描页自动本地 OCR，再生成安全的新 PDF | 复杂版式不原样保留；必须人工复核 OCR 与脱敏结果 |
| OFD | 在 OFD 容器内替换 XML 文本 | 厂商扩展或图片型 OFD 可能需要先转文本型 OFD/OCR |

自动规则适合常见格式，但无法保证识别所有行业术语。正式使用前应维护本单位词表，并人工抽检脱敏文件，确认没有遗漏后再交给外部 AI。

仓库提供了一个不含真实敏感信息的验证文件：[烟草采购清单示例.txt](examples/烟草采购清单示例.txt)。

## 生产安全建议

本轮安全测试方法、结果和剩余风险参见 [本地安全与渗透测试报告](docs/PENETRATION_TEST_REPORT.md)。

- 将 `MAPPING_ENCRYPTION_KEY` 纳入密钥备份。该密钥丢失后，历史任务无法反匿名。
- 本机标识只是映射归属提示，真正的安全边界是只保存在部署主机上的 `MAPPING_ENCRYPTION_KEY`。备份或迁移时必须将数据库、媒体文件和密钥作为一个受控整体；不要把密钥提交到 Git。
- 通过主机防火墙限制 `5291` 只对可信内网开放；需要跨网访问时在上层网关启用 HTTPS。
- 定期备份 MySQL 和 `media_data` Docker 卷，两者缺一都会影响历史任务恢复。
- 制定任务数据保留周期，并按组织制度清理原文件、处理稿、正式文件和数据库记录。
- 当前版本未内置账号权限；多人环境上线前应接入组织统一身份认证或在 Nginx 前增加访问控制。
