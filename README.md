# 隐数盾：烟草行业数据脱敏平台

面向内网部署的可逆数据脱敏应用。原始文件在本地完成敏感信息替换，脱敏稿可交由外部 AI 校对、总结或改写；AI 处理后的文件再上传本系统，使用原任务的加密映射恢复正式信息。

## 功能

- 支持 `.xls`、`.docx`、`.pdf`、`.ofd`、`.txt`。
- 本地 UIE-micro 与规则词典协同识别单位/部门、人员姓名、电话、身份证、邮箱和地址，不把业务文件发送到云端。
- Web 页面可选择“临时调用”或“模型常驻”；也可维护烟草专卖局、卷烟厂、供应商和人员标签。
- 每个任务使用独立匿名标记，例如 `【单位_A1B2_001】`。
- 匿名映射使用 Fernet 对称加密后保存到 MySQL，不提供明文映射下载。
- 脱敏文件下载、原任务关联、反匿名恢复和任务历史均在同一工作台完成。
- 上传文件标题自动生成任务名称；文件名中的已识别敏感信息同步脱敏，反匿名时恢复正式文件名；每条记录保存原始上传、脱敏输出、反匿名上传稿和正式输出。
- 删除记录时同步删除该任务的全部保存文件和加密映射。
- Docker Compose 一键本地部署，对外端口固定为 `5291`。

本地识别器覆盖烟草单位全称、常见部门、负责人/组长/成员/评委等角色上下文人名、人员名单、表格独立姓名、电话、证件、邮箱和规范地址，并由 UIE-micro 补充识别上下文中的低频人名、单位和地址。它兼容 PDF 提取后文字间出现空格、Word 文本框以及 OFD `TextCode` 拆分等常见情况。正文和文件名共用可逆映射：脱敏文件名使用 `ANON_类别_任务码_序号` 安全标记，正式文件名在反匿名时恢复。规则或模型无法判断的简称、内部代号可在“训练标签”页面维护，或通过“指定敏感词”逐行补充；命中数量为 0 时不要直接把输出文件当作有效脱敏结果。

“临时调用”只在本次脱敏期间加载 UIE-micro，任务结束后释放模型内存，适合偶尔使用或内存较小的电脑，但每次任务会有模型启动等待；“模型常驻”首次加载后保留模型进程，连续处理速度更快，空闲时约占用 0.9～1.5 GB 内存。添加、修改或停用识别标签时，系统会加密保存训练样本；新标签会立即作为精确词库参与后续任务，同时作为未来批量微调 UIE 的训练数据。系统不会在每次点击保存时即时重训模型，以免界面卡顿或少量样本导致模型效果退化。

## 技术结构

```text
浏览器 :5291
    │
  Nginx ── /api/* ── Django REST API ── MySQL 8
    │                         │
    └── Vue 3 + Bootstrap 5   ├── 加密映射与本地文件处理
                              └── 本地 UIE-micro 进程（临时/常驻）
```

## Windows + WSL2 + Docker 部署

Windows 10/11 中国大陆网络环境只需一个 `install-wsl-docker-cn.ps1`。脚本先检测系统，检测合格后询问是否继续；选择“是”后检查现有 WSL2、Ubuntu、Docker 和 Compose，版本符合要求时自动跳过重复安装。在管理员 PowerShell 中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install-wsl-docker-cn.ps1
```

如只做检测，可为同一脚本添加 `-CheckOnly`。完整流程、支持版本、国内镜像配置、重启续跑和故障排查参见 [Windows + WSL2 + Docker 中国大陆一键安装说明](docs/WSL_DOCKER_CN_INSTALL.md)。

UIE-micro 的最低部署配置为 4 个逻辑核心、8 GB 内存和 30 GB 可用空间，建议配置为 6 个及以上逻辑核心、16 GB 内存和 40 GB 可用 SSD 空间。8～15 GB 内存的主机建议在 Web 页面选择“临时调用”。首次构建后端镜像时会从配置的中国大陆 PyPI 源安装 Paddle 依赖，并把 UIE-micro 模型封装进本地镜像，耗时和镜像体积会比纯规则版本增加。

安装过程持续记录到 `.runtime/install-support-latest.log`。如果脚本报错、窗口异常关闭或需要协助排查，直接发送这一份日志即可；不要发送包含密码和加密密钥的 `.env` 文件。正常及已捕获的失败运行会另存带时间的历史日志，未正常结束的日志会在下次运行前自动抢救归档。

WSL 系统包只使用微软官方来源；`Auto`/`Web` 会先对 GitHub 官方直连及大陆反向代理做小文件实测，验证文件头后选择最快通道，再通过 Windows 原生 `curl.exe` 下载微软签名的 WSL MSI 和微软清单中的 Ubuntu 包。窗口每 0.5 秒在同一个动态进度区域内更新真实百分比、已下载/总大小、瞬时及平均 MB/s，不会连续新增下载记录，并支持断点续传和缓存复用。首次系统资源检测拆分为 10 个可见小步骤，逐项记录 WMI、DISM、端口和镜像源选择。Ubuntu、Docker CE 与 PyPI 会用 `curl.exe` 对清华、阿里云、USTC、华为云、腾讯云、北外 BFSU 和南京大学 NJU 做小流量实测并选择最快可用源；npm 会在 npmmirror、华为云和腾讯云中选择最快候选，全部不可用时再回退官方源。单个候选失败或超时不会终止整个安装，也不会再因 Windows Server 后台网页请求异常而误报所有源不可用。容器部署另拆分为 11 个可见小步骤，持续显示已等待时间、最近的 Docker 输出及健康检查次数；如果旧 MySQL 数据卷密码与当前 `.env` 不一致，脚本会在检测到 `ERROR 1045` 后通过禁用网络的临时维护容器无损同步账号密码，不删除数据库、任务记录或文件。脚本还会创建 `DataAnonymizationWslKeepAlive` 登录自动启动任务，使 WSL、Docker 和容器在安装窗口关闭后继续运行，并从 Windows 连续检查网站稳定性后才报告完成。代理传输内容仍必须通过官方 SHA-256 和微软数字签名校验。现有 WSL、发行版和 Docker 检测有 12～20 秒超时保护；旧版 `wsl.exe` 的 UTF-16/系统代码页输出也会自动解码，避免中文乱码。

安装完成后优先访问 [http://127.0.0.1:5291](http://127.0.0.1:5291)，`http://localhost:5291` 为备用地址。日常运维统一进入 WSL2：

```powershell
wsl -d Ubuntu-24.04 -u root
```

进入 WSL 后切换到项目目录，再执行 Docker Compose 命令：

```bash
cd /mnt/d/code/dataanonymization  # 按实际项目路径修改
docker compose ps                 # 查看状态
docker compose logs -f            # 查看日志
docker compose down               # 停止服务，保留数据
docker compose up -d              # 重新启动
```

## Linux 主机 + Docker 部署

Linux 服务器无需 WSL，推荐 Ubuntu Server 22.04/24.04 LTS。Docker Engine 支持范围为 `>=24.0 且 <30.0`，Compose 插件为 `>=2.20 且 <6.0`；现有版本符合范围时无需重新安装。安装 Docker、配置中国大陆镜像、安全密钥、防火墙、启动与备份步骤参见 [Linux 主机 Docker 部署说明](docs/LINUX_DOCKER_DEPLOYMENT.md)。

## 使用流程

1. 在“数据匿名”选择 UIE-micro 的“临时调用”或“模型常驻”，上传原文件并勾选识别类型。
2. 下载脱敏文件，交由 AI 进行所需的内容处理。
3. 不要删除、拆分或改写正文中的 `【类别_任务码_序号】` 或文件名中的 `ANON_类别_任务码_序号` 标记。
4. 返回“数据反匿名”，选择原脱敏任务，上传 AI 处理稿并下载正式文件。

长期复用的单位、人名和地址请在“训练标签”页面添加；只用于当前任务的内容可填写在“指定敏感词”中。为兑现“每次增加或修改标签都作为训练数据”的要求，当前任务填写的指定敏感词也会加密保存为全局标签，并在后续任务中继续生效。停用标签只停止精确词库匹配，已有训练样本仍保留，便于审计和未来批量微调。

指定敏感词每行一个；可用 `类型|内容` 标注：

```text
单位|某某市烟草专卖局
单位|某某卷烟厂
人名|张三
某内部项目代号
```

## 文件处理说明

PDF/OFD 的详细实现与限制参见 [PDF 与 OFD 处理机制说明](docs/FILE_PROCESSING_GUIDE.md)。

| 格式 | 处理方式 | 注意事项 |
|---|---|---|
| TXT | 保留检测到的文本编码，必要时转 UTF-8 BOM | 结构保真度最高 |
| DOCX | 处理正文、表格、页眉和页脚 | 跨多个富文本样式的敏感词会合并到首个样式段 |
| XLS | 保留工作簿和主要单元格样式 | 只处理文本单元格，不改写公式 |
| PDF | 提取文本后生成排版规范的新 PDF | 复杂版式不原样保留；扫描件必须先 OCR |
| OFD | 在 OFD 容器内替换 XML 文本 | 厂商扩展或图片型 OFD 可能需要先转文本型 OFD/OCR |

自动规则适合常见格式，但无法保证识别所有行业术语。正式使用前应维护本单位词表，并人工抽检脱敏文件，确认没有遗漏后再交给外部 AI。

仓库提供了一个不含真实敏感信息的验证文件：[烟草采购清单示例.txt](examples/烟草采购清单示例.txt)。

## 生产安全建议

本轮安全测试方法、结果和剩余风险参见 [本地安全与渗透测试报告](docs/PENETRATION_TEST_REPORT.md)。

- 将 `MAPPING_ENCRYPTION_KEY` 纳入密钥备份。该密钥丢失后，历史任务无法反匿名。
- 通过主机防火墙限制 `5291` 只对可信内网开放；需要跨网访问时在上层网关启用 HTTPS。
- 定期备份 MySQL 和 `media_data` Docker 卷，两者缺一都会影响历史任务恢复。
- 制定任务数据保留周期，并按组织制度清理原文件、处理稿、正式文件和数据库记录。
- 当前版本未内置账号权限；多人环境上线前应接入组织统一身份认证或在 Nginx 前增加访问控制。
