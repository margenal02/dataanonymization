# 隐数盾本地安全与渗透测试报告

## 1. 报告信息

- 测试日期：2026-08-12
- 测试对象：烟草行业数据脱敏平台
- 测试地址：`http://127.0.0.1:5291`
- 测试范围：Vue 前端、Django REST API、文件上传与解析、任务记录、文件下载与删除
- 身份认证：按业务要求不启用登录
- 测试性质：开发环境内部安全测试，不替代具备资质的第三方等保测评或正式渗透测试

## 2. 总体结论

本轮测试未发现可直接利用的高危或严重代码漏洞。功能回归 10 项全部通过，运行中黑盒用例 10 项全部通过，Python 与 NPM 依赖升级后均未检出已知漏洞，Bandit 静态扫描未报告问题。

系统适合部署在受控内网或 VPN 环境。由于明确不启用登录，任何能够访问 5291 端口的人员都可以查看任务记录、下载处理文件或删除任务。这是当前方案最重要的剩余风险，必须由网络访问控制承担隔离责任，不得直接暴露到互联网。

## 4. 已实施安全控制

- 文件扩展名、文件头和内部格式联合校验。
- PDF 页数上限、上传体积上限。
- DOCX/OFD 压缩条目数量、单项大小、总体积和压缩比限制。
- 拒绝压缩包内部绝对路径、`..` 路径及加密条目。
- 文件名去目录、非法字符和 HTML 特殊字符处理。
- 匿名映射使用 Fernet 加密存储。
- 每个任务使用独立 UUID 和匿名标记命名空间。
- 删除要求任务 UUID 二次确认，并同步删除整个任务目录。
- API 匿名访问频率限制为每来源地址每分钟 180 次。
- MySQL 不对宿主机直接开放端口。
- Nginx 配置 CSP、Permissions-Policy、X-Frame-Options、X-Content-Type-Options 和 Referrer-Policy。
- 生产配置默认关闭 Django Debug 并限制 Host。
- Windows 安装脚本的 WSL MSI 只接受 GitHub 官方发布接口提供的资产；下载后校验官方 SHA-256（接口提供时）及微软 Authenticode 数字签名。
- Ubuntu `.wsl` 包从微软官方发行版清单解析地址，并校验清单中的 SHA-256。
- 大陆反向代理仅作为公开 WSL MSI 的可选传输通道；测速样本先验证 MSI 文件头，完整文件校验失败会立即删除并拒绝安装。代理不接触项目文件、脱敏数据、数据库口令或映射密钥。

## 5. 剩余风险

### 高风险：无身份认证

这是用户确认接受的业务要求。影响包括：

- 同一网络内任何访问者均能查看全部任务名称与记录。
- 访问者可下载脱敏文件和已恢复的正式文件。
- 访问者可删除任务及全部存留文件。
- UUID 不是访问控制手段，不能替代账号权限。

必须采取以下补偿措施：

- 只监听或放行可信内网/VPN 地址。
- 主机防火墙对 5291 设置来源 IP 白名单。
- 禁止公网端口映射。
- 若跨网访问，在上层 VPN 或反向代理启用身份验证与 HTTPS。

### 中风险：处理文件包含真实敏感信息

映射已加密，但原始文件、反匿名上传稿和正式文件目前以普通文件保存。建议使用 BitLocker/LUKS 加密数据盘，限制 Docker 数据卷或 `backend/media` 的操作系统权限，并制定备份与销毁制度。

### 中风险：自动识别存在漏报

正则规则不可能覆盖全部烟草行业单位、人员和内部项目名称。必须维护“指定敏感词”词表，并在外发 AI 之前人工抽检脱敏结果。

### 中风险：解析复杂文档的资源消耗

已增加大小、页数和压缩炸弹限制，但未执行高强度持续 DoS/压力攻击。生产环境建议配置 CPU/内存容器限额、Nginx 请求限速和监控告警。

### 低风险：没有 HTTPS

纯本机或隔离内网可接受。跨主机使用时应在 Nginx 或上层网关配置内部 CA 证书。

### 低风险：安装包反向代理的元数据暴露与可用性

中国大陆网络下，脚本可能选择第三方 HTTPS 反向代理传输公开的微软 WSL MSI。代理可观察客户端 IP、请求时间和公开文件 URL，也可能限速、中断或停止服务；它不会接触应用业务数据。内容完整性由 GitHub 官方 SHA-256 和微软数字签名验证承担，不能把代理可用性等同于供应链可信。高安全环境可使用 `-WslDownloadChannel Store` 禁用代理测速，或通过单位批准的制品库离线分发已验证官方包。

### 低风险：安装支持日志包含主机元数据

安装支持日志不会主动记录 `.env` 密码、应用密钥或令牌，但会包含主机路径、局域网 IP、镜像名称、容器状态、健康检查输出和异常调用栈。`.runtime` 已排除在 Git 提交之外；仍应将日志视为内部运维资料，通过受控渠道传递并按组织保留期限清理，不应发布到公开问题或公共网盘。
