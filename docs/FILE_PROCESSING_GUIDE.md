# PDF 与 OFD 处理机制说明

## PDF

当前 PDF 采用“提取文本、替换敏感信息、重新生成 PDF”的方式处理：

1. 校验文件头必须以 `%PDF-` 开始。
2. 使用 pypdf 读取 PDF，拒绝损坏文件、带密码文件以及超过 1000 页的文件。
3. 逐页提取文本；如果所有页面都没有可提取文本，则判定为扫描件并提示先执行 OCR。
4. 在提取出的文本中识别敏感信息并替换为匿名标记。
5. 使用 ReportLab、A4 页面和中文字体重新生成新的 PDF。
6. 反匿名时再次提取脱敏稿文本，将标记替换为原值并重新生成正式 PDF。

局限：原 PDF 的字体、坐标、表格、印章、图片、签名、批注和复杂版式不会原样保留。因此 PDF 当前属于“内容可逆、版式不保真”。正式公文优先使用 DOCX；扫描 PDF 必须先 OCR；含电子签章 PDF 处理后签名会失效。

## OFD

OFD 本质通常是 ZIP 容器。当前采用“保留容器结构，仅替换 XML 中的文本”方式：

1. 验证文件为有效 ZIP，并必须包含 `OFD.xml`。
2. 检查内部路径穿越、加密条目、条目数量、解压总体积、单项大小和异常压缩比。
3. 逐项读取容器内容，只处理以 `.xml` 结尾且可按 UTF-8 解码的文件。
4. 在 XML 原始文本中直接替换敏感信息，不解析或执行 XML 外部实体。
5. 图片、字体、印章等二进制资源原样复制，目录结构保持不变。
6. 反匿名时对相同 XML 内容执行标记恢复。

局限：如果文字被拆成多个 XML 节点、使用厂商自定义编码、以矢量路径/图片保存或属于扫描型 OFD，当前规则可能无法识别。XML 中直接替换为更长标记也可能影响依赖固定坐标的版式。电子签章和数字签名在任何内容变化后通常都会失效，处理后必须重新签章。
