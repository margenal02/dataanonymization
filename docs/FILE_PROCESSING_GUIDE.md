# PDF 与 OFD 处理机制说明

默认单文件上传上限为 200 MB，可通过 `.env` 中的 `MAX_UPLOAD_SIZE_MB` 下调。Web 页面会读取服务端上限并在选择文件时校验；Nginx 对超限请求返回 JSON 格式的 413 错误，不会再显示无法识别的 HTML 响应。PDF 最多 1000 页；其中默认最多允许 300 个无文本页进入本地 OCR，提取和 OCR 后的总文字上限为 500000 字符。

## 敏感信息识别

系统在本机完成识别，不把文件发送给外部模型或云服务。当前采用“规则词典 + UIE-micro + 人工训练标签”的混合识别，面向中文烟草公文、合同和表格，支持：

- 烟草专卖局、烟草公司、中烟工业公司、卷烟厂、复烤厂及常见公司/事业单位全称；
- 正文中的多家单位，以及单位、供应商、采购人、中标人、承办单位等标签后的名称；
- 项目负责人、联系人、经办人、审核人、审批人、组长、副组长、主任、经理、领队、教练、评委等角色附近的人名；
- “成员、组员、参加人员、参赛人员、工作人员、专家名单”等名单以及 DOCX/XLS/TXT 表格中单独出现的常见中文姓名；
- 手机、座机、400 电话、身份证、统一社会信用代码、护照/许可证号码和电子邮箱；
- 带标签的地址，以及包含省、市、区县、道路门牌的规范地址；
- 山东中烟、云南中烟等行业常见简称，带“产品/品牌/品名/模块”上下文的烟草产品，以及文山、曲靖等产区上下文；
- PDF 提取后汉字或号码之间被插入空格的常见情况。

UIE-micro 负责从已经安全提取的文本中补充人名、单位/部门、品牌/产品、产区/地点和地址；电话、证件、邮箱以及行业格式仍由确定性规则识别。各模型类别使用独立阈值，人名还必须通过中文姓名结构校验；同一文字被预测为多种类别时按置信度和业务优先级只保留一种，并在结果区显示被过滤的低置信或冲突数量。低频姓名、简称、内部代号或缺少上下文的任意词仍可能漏识；这类内容可用“单位|内容”“人名|内容”“产品|内容”“产区|内容”等形式补充。

上传后的第一阶段只把规则、标签和模型结果作为候选，不允许直接下载。Web 人工确认区按候选项显示最多三处原文前后文并高亮命中文字，同时显示规则/本地标签/模型来源和模型置信度。操作人员必须确认勾选、取消误报、修改类别或按 `类别|内容` 补录漏项，之后系统才将任务改为“脱敏完成”并开放下载；下载接口也会拒绝状态仍为“待人工确认”的任务。补录项立即进入加密精确词库，取消项作为加密否决样本保存。已完成任务仍可重新校正；如果已有反匿名上传稿或正式文件，校正后这些旧文件会被删除，必须基于新脱敏稿重新执行反匿名。

### UIE-micro 运行方式

- **临时调用（推荐）**：本次任务开始时加载模型，识别结束后终止模型进程并归还内存。适合低频使用或 8～15 GB 内存的电脑；每次任务需要额外等待模型启动。
- **模型常驻**：首次任务加载后保留同一个模型进程，后续任务无需重新加载。适合连续批量处理或 16 GB 及以上内存的主机；空闲时约占用 0.9～1.5 GB 内存。

Web 页面切换到“临时调用”会立即卸载已经常驻的模型；切换到“模型常驻”会预热模型并显示当前状态。同一时刻只允许一个 UIE 推理请求进入模型进程，避免多个 Django 工作进程各自加载模型造成内存翻倍。UIE 加载或推理失败时任务会明确失败，不会悄悄退化为只用规则并生成可能漏报的文件。

### 训练标签与数据留存

添加、修改、停用标签、任务内“指定敏感词”以及确认页面的补录、类别修正和否决都会生成加密训练记录。标签内容、候选上下文和训练样本使用 `MAPPING_ENCRYPTION_KEY` 加密后存入 MySQL，不在日志中返回明文历史。确认页面为了让操作人员核对当前任务，会在本地 API 响应中返回候选项附近的原文，因此端口 5291 必须限制在可信内网。当前版本有两层生效机制：

1. 标签保存后立即作为精确词库用于后续任务，修正结果无需等待训练。
2. 每次变更保留为未来批量微调 UIE-micro 的训练数据，但不会在每次保存时即时重训基础模型，以免阻塞 Web 操作或被少量错误样本带偏。

停用标签后不再参与精确匹配，但对应训练历史仍会保留用于审计；删除某个脱敏任务只删除该任务文件和映射，不会自动删除全局训练标签。需要停止某个标签时应在“训练标签”页面停用。备份和销毁制度必须同时覆盖 MySQL 训练数据以及 `MAPPING_ENCRYPTION_KEY`。

文件正文与文件名使用同一个加密映射。文件名会作为独立文本同时交给规则和 UIE-micro 检查，正文已经命中的敏感词也会直接复用；“姓名+方案/报告/名单/简历”等常见标题中的姓名会主动识别。正文采用 `【单001】`、`【人001】`、`【品001】` 等短标记，文件名采用对应的 `ANON_单001` 等标记，反匿名上传稿保留标记时，系统会恢复原名称并输出“正式版”文件。任务列表默认展示脱敏或恢复后的文件名，不直接展示原始敏感文件名。

## DOCX

DOCX 处理会遍历正文、表格、页眉页脚、批注相关部件及文本框中的 `w:t` 文字节点。识别时把同一段落的相邻文字节点合并查看，因此可以命中被多个字体或样式节点拆开的单位/人名；写回时根据原文与脱敏文本的差异，只删除命中的原文字区间并把短标记放到该区间的起始节点。未命中的文字节点、段落、表格、字体、字号、颜色、加粗、下划线等 XML 结构不再整体重写。

局限：敏感文字本身跨多个样式时，短标记继承其起始文字节点的样式；图片、艺术字轮廓或嵌入对象中的文字不能直接处理，仍需 OCR。任何内容修改都会使已有数字签名失效。

## PDF

当前 PDF 采用“逐页提取或本地 OCR、替换敏感信息、重新生成 PDF”的方式处理：

1. 校验文件头必须以 `%PDF-` 开始。
2. 使用 pypdf 读取 PDF，拒绝损坏文件、带密码文件以及超过 1000 页的文件。
3. 逐页提取文本；去除空白后少于 `PDF_OCR_MIN_TEXT_CHARS` 的页面判定为扫描页。
4. 扫描页先由 Poppler 以默认 180 DPI、最长边不超过 3508 像素渲染，再调用 Tesseract `chi_sim+eng` 在容器内识别简体中文和英文。临时页面图像在单页处理结束后立即删除。
5. Web 上传请求进行期间会轮询任务记录，显示当前 OCR 页、需要 OCR 的总页数、生成 PDF 页数及百分比。
6. 在提取或 OCR 文本中识别敏感信息并替换为匿名标记。
7. 使用 ReportLab、A4 页面和中文字体重新生成不含原扫描像素的新 PDF。
8. 反匿名时再次提取脱敏稿文本，将标记替换为原值并重新生成正式 PDF。

局限：原 PDF 的字体、坐标、表格、印章、图片、签名、批注和复杂版式不会原样保留。因此 PDF 当前属于“内容可逆、版式不保真”。OCR 可能把低清文字、印章遮挡文字或行业生僻词识错；必须下载脱敏稿人工核对，并使用“校正识别”补充漏项后再外发。含电子签章 PDF 处理后签名会失效。DOCX 的正文、表格、页眉页脚和文本框均会处理，但 DOCX 图片中的文字仍需先 OCR。

OCR 默认参数可通过 `.env` 调整：`PDF_OCR_ENABLED`、`PDF_OCR_LANGUAGES`、`PDF_OCR_DPI`、`PDF_OCR_MAX_IMAGE_DIMENSION`、`PDF_OCR_MIN_TEXT_CHARS`、`PDF_OCR_MAX_PAGES`、`PDF_OCR_MAX_TOTAL_CHARS` 和 `PDF_OCR_PAGE_TIMEOUT_SECONDS`。关闭 OCR 后，只要存在无足够文本层的页面，任务就会明确失败，避免静默漏掉扫描页。Tesseract 多语言 `-l` 与页面分割参数的含义参见 [Tesseract 官方命令行文档](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)。

## OFD

OFD 本质通常是 ZIP 容器。当前采用“保留容器结构，仅替换 XML 中的文本”方式：

1. 验证文件为有效 ZIP，并必须包含 `OFD.xml`。
2. 检查内部路径穿越、加密条目、条目数量、解压总体积、单项大小和异常压缩比。
3. 逐项读取容器内容，使用禁止网络、DTD 和外部实体的安全 XML 解析器处理 `.xml` 文件。
4. 同一个 `TextObject` 中拆分到多个 `TextCode` 节点的文字会先合并识别，再写回匿名标记。
5. 图片、字体、印章等二进制资源原样复制，目录结构保持不变。
6. 反匿名时对相同 XML 内容执行标记恢复。

局限：跨越多个 `TextObject` 的文字、厂商私有编码、矢量路径、图片或扫描型 OFD 仍可能无法识别。更长的匿名标记也可能影响依赖固定坐标的版式。电子签章和数字签名在任何内容变化后通常都会失效，处理后必须重新签章。
