# PDF 与 OFD 处理机制说明

## 敏感信息识别

系统在本机完成识别，不把文件发送给外部模型或云服务。当前识别器面向中文烟草公文、合同和表格，支持：

- 烟草专卖局、烟草公司、中烟工业公司、卷烟厂、复烤厂及常见公司/事业单位全称；
- 正文中的多家单位，以及单位、供应商、采购人、中标人、承办单位等标签后的名称；
- 项目负责人、联系人、经办人、审核人、审批人等角色附近的人名；
- 人员名单和 DOCX/XLS/TXT 表格中单独出现的常见中文姓名；
- 手机、座机、400 电话、身份证、统一社会信用代码、护照/许可证号码和电子邮箱；
- 带标签的地址，以及包含省、市、区县、道路门牌的规范地址；
- PDF 提取后汉字或号码之间被插入空格的常见情况。

识别采用本地规则与上下文词典，不是可以理解任意自然语言的通用大模型。低频姓名、简称、内部代号或缺少上下文的任意词仍可能漏识；这类内容可在页面的“指定敏感词”中逐行补充，并可用“单位|内容”“人名|内容”等形式指定类别。处理完成后应查看页面显示的各类命中数量；如果全部为 0，不应直接把输出文件作为正式脱敏结果。

## PDF

当前 PDF 采用“提取文本、替换敏感信息、重新生成 PDF”的方式处理：

1. 校验文件头必须以 `%PDF-` 开始。
2. 使用 pypdf 读取 PDF，拒绝损坏文件、带密码文件以及超过 1000 页的文件。
3. 逐页提取文本；如果所有页面都没有可提取文本，则判定为扫描件并提示先执行 OCR。
4. 在提取出的文本中识别敏感信息并替换为匿名标记。
5. 使用 ReportLab、A4 页面和中文字体重新生成新的 PDF。
6. 反匿名时再次提取脱敏稿文本，将标记替换为原值并重新生成正式 PDF。

局限：原 PDF 的字体、坐标、表格、印章、图片、签名、批注和复杂版式不会原样保留。因此 PDF 当前属于“内容可逆、版式不保真”。正式公文优先使用 DOCX；扫描 PDF 必须先 OCR；含电子签章 PDF 处理后签名会失效。DOCX 的正文、表格、页眉页脚和文本框均会处理，但图片中的文字仍需先 OCR。

## OFD

OFD 本质通常是 ZIP 容器。当前采用“保留容器结构，仅替换 XML 中的文本”方式：

1. 验证文件为有效 ZIP，并必须包含 `OFD.xml`。
2. 检查内部路径穿越、加密条目、条目数量、解压总体积、单项大小和异常压缩比。
3. 逐项读取容器内容，使用禁止网络、DTD 和外部实体的安全 XML 解析器处理 `.xml` 文件。
4. 同一个 `TextObject` 中拆分到多个 `TextCode` 节点的文字会先合并识别，再写回匿名标记。
5. 图片、字体、印章等二进制资源原样复制，目录结构保持不变。
6. 反匿名时对相同 XML 内容执行标记恢复。

局限：跨越多个 `TextObject` 的文字、厂商私有编码、矢量路径、图片或扫描型 OFD 仍可能无法识别。更长的匿名标记也可能影响依赖固定坐标的版式。电子签章和数字签名在任何内容变化后通常都会失效，处理后必须重新签章。
